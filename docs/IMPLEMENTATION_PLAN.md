## 各PRの共通レビュー条件

- GAME_SPECと実装対象の個別Issueを参照し、実装対象と未実装範囲を説明する。Issue #1は履歴として保持する。
- 対応するデータ・純粋関数・意味のある単体テストを同じPRで追加する。
- typecheck / lint / Vitest / buildを通し、UI変更では対象端末の操作確認を記録する。
- 仕様書・設計・READMEの開発状況を更新する。仮定と理由、未確定仕様をPRに残す。
- 数値や処理順の変更は該当Issue・PRで理由と変更後仕様を説明し、GAME_SPECを同期する。

## フェーズ3の実装状況（Issue #7）

H2取得/即時使用/最大3/持ち越し、BOOST全消費と乗算、CHAIN追加3PULL・再連鎖、CHARGE+5を実装済み。
×1/10/100/1000は同じ実PULLエンジンを反復する。CHAIN群をFIFOで消化後に次の基本PULLへ進む。
最大100,000実PULL/呼び出しで停止し、基本/CHAINの残数を保持して再開できる。新規操作の割り込みは拒否する。
結果は固定サイズの集計と最終状態。RNGは実PULLごとに3回のみ消費し、分割間でも同じストリームを継続する。
単一/一括、JSON往復した状態での再開、連鎖の上限、非破壊・安全整数を単体/統合テストで検証する。
UI接続・保存・Stage解放は未実装。次はフェーズ4の手動SPECIAL・JACKPOT。
JACKPOTの区間処理は追加効果後・討伐確定前へ挿入し、CHAINを含む実PULL単位で集計する。
