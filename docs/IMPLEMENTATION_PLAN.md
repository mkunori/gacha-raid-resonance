## 各PRの共通レビュー条件

- 親Issue #1を参照し、実装対象と未実装範囲を説明する。親Issue全体を基盤PRでcloseしない。
- 対応するデータ・純粋関数・意味のある単体テストを同じPRで追加する。
- typecheck / lint / Vitest / buildを通し、UI変更では対象端末の操作確認を記録する。
- 仕様書・設計・READMEの開発状況を更新する。仮定と理由、未確定仕様をPRに残す。
- 数値や処理順を変更する前に親Issueへ理由・変更後仕様を記載する。

## フェーズ1の実装状況（Issue #3）

通常ガチャの独立抽選、4フォーカス、RNG注入（レアリティ→属性→追加効果、各1回）、

全累積境界の隣接値/一致値、固定列・Mulberry32固定シードによる再現性をVitestで検証する。
公開APIはTECHNICAL_DESIGNの「通常ガチャの公開API」を参照。
